## Summary

Every project in Fermata already carries structured metadata. Turn that into a browsable
static site — searchable, filterable, dark-mode, zero-JS-framework — published to GitHub Pages
on every merge to `main`. This is the public face of the repo, and it's also the proving
ground for the project-browsing UX that [FB-0202](../../ecosystem/FB-0202-project-registry-browse/)
will later build for real on the website.

---

## Context

- **Why now:** `projects/INDEX.md` is a table in a Markdown file. It works, and it will not
  scale past about thirty projects or survive anyone's attention on a phone.
- **Why static:** no server, no build-time secrets, no runtime cost, and it can't break the
  repo. It also forces the metadata to be genuinely sufficient — if the gallery can't render
  a good card, `fermata.json` is missing something, and that's useful pressure.
- **Downstream:** this bounty **blocks** FB-0202. The card design, filter model, and search
  index built here are the spec the hosted version implements.

---

## Out of scope

- No React, Vue, Svelte, or bundler. Plain HTML/CSS/JS output, generated by a Node script with
  no dependencies — matching the rest of `scripts/`.
- No server-side anything, no analytics, no third-party trackers or fonts loaded at runtime.
- Not running project code. Cards are metadata and README text, not live demos.
- Not touching `projects/INDEX.md`. The Markdown index stays for people reading in the repo.

## Acceptance criteria

- [ ] `npm run gallery` generates a complete static site into `site/dist/` from the current
      project tree, with no network access required.
- [ ] The index page lists every project as a card showing display name, description, category,
      status, platforms, tags, and authors.
- [ ] Client-side search matches against name, description, and tags, and filters exist for
      category, status, and platform. Filter state is reflected in the URL so views are
      shareable.
- [ ] Each project gets a detail page at a stable path (`/projects/<category>/<name>/`) that
      renders the project's own `README.md`.
- [ ] The site is fully usable with JavaScript disabled: all projects and their detail pages
      are present in the HTML: search and filtering are the only things that degrade.
- [ ] Lighthouse scores ≥ 95 for Performance and Accessibility on the index page, with the
      report attached to the PR.
- [ ] Dark mode follows `prefers-color-scheme`, and both themes meet WCAG AA contrast.
- [ ] A GitHub Pages workflow deploys on every push to `main`, and the live URL is linked from
      `README.md`.

### Bonus

- [ ] A `search-index.json` artifact is emitted alongside the site, documented as the
      consumable contract for FB-0202 and the desktop app.

## Definition of done

- All acceptance criteria checked, with the Lighthouse report and a deployed preview linked in
  the PR.
- Generated output is deterministic — running the generator twice on an unchanged tree
  produces identical bytes.
- No runtime dependencies; build-time dependencies limited to Node built-ins.
- If [FB-0005](../../design/FB-0005-visual-identity-kit/) has landed, the gallery uses that
  palette and mark. If it hasn't, use the README's existing colours and leave the theming in
  one CSS custom-property block so it can be swapped in one commit.
- Reviewed and approved per [GOVERNANCE.md](../../../GOVERNANCE.md#review-rules) — `l` size
  needs an Approver plus a second reviewer.

## Getting started

```bash
git clone https://github.com/ScottyVenable/fermata.git
cd fermata
node -e "import('./scripts/lib/repo.mjs').then(m=>m.findProjects().then(console.log))"
cat projects/tools/ai/vivarium/fermata.json
```

Files worth reading first:

- `scripts/lib/repo.mjs` — `findProjects()` and `readJson()` give you the whole data layer.
- `scripts/organize.mjs` — how the existing index is generated; the same shape, different output.
- `docs/METADATA_SPEC.md` — every field you can render.

Markdown rendering is the one place you'll be tempted to add a dependency. `marked` is already
in the shared registry, so declaring it as a build-time dep is acceptable if you make the case
in the PR — but a small, safe subset renderer is preferred and is part of why this is sized `l`.

## Notes

- Sort order on the index matters more than it sounds. Default to recently-updated, but make
  it switchable.
- Projects with `status: "archived"` should render, dimmed, behind a filter that's off by
  default. Fermata keeps its dead ideas visible — that's the point of the repo.
